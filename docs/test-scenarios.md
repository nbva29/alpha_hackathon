# Проверочные сценарии для экспертов

Это **инструкция для самостоятельной проверки**, а не отчёт о уже выполненном тестировании. Все имена, компании, показатели, документы и решения синтетические. Основные сценарии К-01–К-08 не требуют ИИ. Статусы API приведены для однозначной проверки; интерфейс показывает их человекочитаемые названия. Исходный набор данных создаётся при первом старте. Если в PostgreSQL уже есть демонстрационные заявки, используйте новую заявку и её номер; удалять общий volume для проверки необязательно.

## Подготовка

1. В корне репозитория выполните `docker compose up --build`. Откройте `http://localhost:8080`; интерактивное описание API — `http://localhost:8000/docs`.
2. Используйте учётные записи из README: Анна (`anna@demo.local`), Максим (`maxim@demo.local`), сотрудник (`bank@demo.local`), пароль `demo123`. Пользователи и компании создаются автоматически.
3. Подготовьте маленький **синтетический** PDF до 1 МБ. Не загружайте настоящую банковскую выписку. Для сценариев с двумя заявками используйте разные новые номера.
4. Проверяйте изменения после перезагрузки страницы и через историю заявки. Для спорного результата смотрите ответ соответствующего `/api` запроса в инструментах браузера.

| ID | Действия | Ожидаемый результат |
| --- | --- | --- |
| К-01 Вход и роль | Откройте кабинет без сессии; войдите как Анна. Затем выйдите и войдите как сотрудник. | До входа видна форма входа. Анна попадает в кабинет предпринимателя, сотрудник — в очередь банка. Клиент не видит действия сотрудника. |
| К-02 Каталог и подбор | Под Анной задайте «Закупка оборудования», категорию «Развитие», 1 200 000 ₽ и 24 месяца. Откройте предложения и сравните две карточки. | `Бизнес-рост` подходит; `Бизнес-рост Плюс` не подходит, потому что его минимальная сумма — 3 млн ₽. На карточках видны причины `fits=false`, ставка, диапазон суммы и срока. Подбор не требует модели. |
| К-03 Сохранение профиля и черновика | Под Анной измените один показатель компании, сохраните и обновите страницу. Верните исходное значение. Выберите `Бизнес-рост`, создайте черновик, измените цель и обновите страницу. | Показатель и черновик сохраняются на сервере; номер заявки не меняется, статус `DRAFT`. Профиль и заявка остаются связаны с Анной. |
| К-04 Недостающий документ | Отправьте новый черновик `Бизнес-рост` без документа. Откройте историю и причину. | После синтетической проверки статус `NEEDS_INFO`; указано, что нужен финансовый документ. Это запрос сведений, а не отказ. В истории есть отправка и проверка. |
| К-05 Повторная отправка и сотрудник | В К-04 загрузите подготовленный PDF как `financial`, обновите страницу, отправьте повторно. Выйдите, войдите как сотрудник, откройте заявку и скачайте документ. | Имя документа сохраняется после обновления. Статус `DECISION_PENDING`; обе попытки проверки доступны в данных заявки. Сотрудник видит заявку и документ в очереди. |
| К-06 Одобрение и завершение | Сотрудник одобряет заявку из К-05. Анна вновь входит, открывает результат, принимает условия и нажимает демо-подписание. | Последовательность `APPROVED → OFFER_ACCEPTED → SIGNED_DEMO → DISBURSED_DEMO` видна в истории. Показано, что реальные средства не перечислялись. Повторное подписание завершённой заявки недоступно. |
| К-07 Отказ и запрос сведений | Для отдельной заявки Анны в `DECISION_PENDING` сотрудник выбирает «Запросить сведения» с комментарием; Анна читает его, дополняет заявку и отправляет повторно. Для ещё одной заявки сотрудник выбирает «Отказать» с причиной. | При запросе возникает `NEEDS_INFO`, комментарий виден клиенту, повторная отправка возможна. При отказе — `REJECTED`, причина видна клиенту, принятие предложения и подписание недоступны. Пустой комментарий для отказа/запроса отклоняется. |
| К-08 Разделение клиентов | После создания заявки Анны войдите как Максим и откройте список и прямую ссылку на номер Анны. | Заявка Анны отсутствует в списке; прямая ссылка не раскрывает её данные (`404` на API). У Максима другой профиль. |
| К-09 Негативный скоринг | Под Максимом задайте овердрафт 200 000 ₽ на 6 месяцев, выберите `Овердрафт Лайт`, загрузите синтетическую выписку как `statement` и отправьте. Сотрудник рассматривает заявку. | Заявка доходит до `DECISION_PENDING`. Синтетическая просрочка и показатели уменьшают балл; сотрудник видит причины и может отказать. Одобрение при балле ниже 50 блокируется сервером. |
| К-10 Ограничения документа | В новом черновике попробуйте пустой файл, файл более 1 МБ и неподдерживаемый MIME (если браузер не позволяет выбрать тип, отправьте запрос через `/docs`); затем корректный PDF/PNG/JPEG. | Первые три варианта отклоняются, корректный документ отображается в заявке. Удаление из черновика возможно; после отправки удаление недоступно. |

## Отдельная проверка необязательного ИИ

| ID | Настройка и действия | Ожидаемый результат |
| --- | --- | --- |
| И-01 Без модели | В корневом `.env` задайте `AI_BASE_URL=` и перезапустите backend. Повторите К-02–К-06 и задайте помощнику вопрос о документе для овердрафта. | Кредитный путь работает. Ответ помощника помечен `deterministic-fallback` либо при сравнении `verified-comparison`; карточки источников берутся из справочника. |
| И-02 Локальная модель вне Docker | Запустите OpenAI-совместимый сервер с моделью открытых весов, задайте `AI_BASE_URL=http://host.docker.internal:1234/v1` и точный `AI_MODEL`, перезапустите backend. Спросите помощника: «Какой документ нужен для овердрафта?» | `/api/assistant` возвращает `mode: local-llm`, непустые `sources` с овердрафтами и ответ, соответствующий справочнику. `deterministic-fallback` означает, что вызов модели не подтверждён; проверьте адрес, ID модели и доступность сервера из Docker. |
| И-03 Контекст и проверенное сравнение | На странице своей заявки спросите «Почему нужны сведения и что сделать?». На странице каталога выберите две карточки и попросите их сравнить. | Ответ о заявке относится к текущему номеру; чужой номер нельзя передать. Сравнение не должно придумывать ставки и условия вне карточек. Возможен `verified-comparison`, даже если модель ответила неподходящим текстом. |
| И-04 Модель эксперта | Укажите в корневом `.env` собственные `AI_BASE_URL`, `AI_MODEL`, `AI_API_KEY`; для удалённого HTTPS добавьте `AI_ALLOW_REMOTE=true`. Перезапустите backend и повторите вопрос И-02. | В случае доступного совместимого сервера запрос проходит с Bearer-ключом и ответ имеет `mode: local-llm`. Без сервера или при ошибке остаётся `deterministic-fallback`; К-02–К-06 по-прежнему доступны. |

Распознавание содержания выписки здесь не проверяется: в текущем MVP нет OCR-модели. Для К-05/К-09 проверяются загрузка, хранение, доступ сотрудника и наличие документа, а не извлечение финансовых строк из PDF.
